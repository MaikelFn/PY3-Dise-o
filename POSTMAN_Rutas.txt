CLICKMARKET API - RUTAS PARA POSTMAN
===================================

Base URL: http://localhost:3000

Formato:
- Las rutas marcadas como SESION requieren iniciar sesion primero.
- Postman conserva la cookie clickmarket.sid si estan habilitadas las cookies.
- JSON: usar Header Content-Type: application/json.
- Los IDs de ejemplo deben reemplazarse por IDs existentes en la base de datos.
- Los campos marcados como requeridos por el controlador deben enviarse.


1. AUTENTICACION

POST /api/auth/registro
Acceso: publico
Body JSON:
{
  "nombre": "Ana",
  "apellido": "Perez",
  "correo": "ana@example.com",
  "contrasena": "Clave123!"
}

POST /api/auth/login
Acceso: publico
Body JSON:
{
  "correo": "ana@example.com",
  "contrasena": "Clave123!"
}

GET /api/auth/sesion
Acceso: sesion
Sin body.

POST /api/auth/logout
Acceso: sesion
Sin body.

4. VENDEDORES

GET /api/vendedores
Acceso: publico
Sin body.

GET /api/vendedores/1
Acceso: publico
Sin body.

POST /api/vendedores
Acceso: rol Vendedor
Nota: el usuario de la sesion debe tener rol Vendedor.
Body JSON:
{
  "nombreComercial": "Tienda Ana",
  "descripcion": "Venta de productos variados"
}

PUT /api/vendedores/1
Acceso: rol Vendedor
El ID debe pertenecer al vendedor de la sesion.
Body JSON:
{
  "nombreComercial": "Tienda Ana Actualizada",
  "descripcion": "Venta de tecnologia"
}

DELETE /api/vendedores/1
Acceso: Administrador
Sin body.


5. USUARIOS

GET /api/usuarios/1
Acceso: sesion
Un usuario solo puede consultar su propio ID, salvo Administrador.

PUT /api/usuarios/1
Acceso: sesion
Un usuario solo puede modificar su propio ID, salvo Administrador.
No enviar rol, rolID, RolID ni Rol.
Body JSON:
{
  "nombre": "Ana",
  "apellido": "Perez",
  "correo": "ana@example.com"
}

PATCH /api/usuarios/1/desactivar
Acceso: Administrador
Sin body.
No se permite desactivar al administrador que ejecuta la solicitud.

7. CATEGORIAS, PRODUCTOS E INVENTARIO

GET /api/productos
Acceso: publico
Query params opcionales:
- categoriaID
- vendedorID
- busqueda
Ejemplo: /api/productos?categoriaID=1&vendedorID=1&busqueda=telefono

GET /api/productos/1
Acceso: publico
Sin body.

POST /api/productos
Acceso: sesion
Nota: el usuario debe tener perfil de vendedor activo.
Body JSON:
{
  "categoriaID": 1,
  "nombre": "Teléfono",
  "descripcion": "Teléfono de prueba",
  "precio": 250000
}

POST /api/productos/publicar
Acceso: rol Vendedor
En Body usar form-data.
Campos:
- categoriaID: 1
- nombre: Teléfono publicado
- descripcion: Producto creado mediante publicación
- precio: 250000
- cantidad: 10
- imagen: archivo JPG, PNG o WebP, máximo 5 MB

PUT /api/productos/1
Acceso: sesion
Nota: el usuario debe tener perfil de vendedor activo y ser propietario.
Body JSON:
{
  "categoriaID": 1,
  "nombre": "Teléfono actualizado",
  "descripcion": "Descripción actualizada",
  "precio": 260000
}

DELETE /api/productos/1
Acceso: sesion
Nota: el usuario debe tener perfil de vendedor activo y ser propietario.
Sin body.
